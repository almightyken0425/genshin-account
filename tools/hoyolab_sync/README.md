# HoYoLAB 資料同步

本機工具讀取原神與絕區零的角色、技能、穿戴裝備及面板，先預覽差異，再更新 GitHub main。網站繼續以同一份正式帳號資料為來源，不建立另一份帳號資料庫。

## 開啟與更新

電腦需有 Python 3.11 以上及已登入的 GitHub CLI。Mac 開啟 [啟動同步.command](啟動同步.command)，Windows 開啟 [啟動同步.cmd](啟動同步.cmd)。啟動程式會在專案獨立環境安裝固定版本的套件，再開啟 [本機同步頁](http://127.0.0.1:59672)。請保留啟動視窗。

| 操作 | 結果 |
| --- | --- |
| 在官方 HoYoLAB 使用 Apple 或其他方式登入，依本機頁說明填入指定 Cookie 值 | 本機工具確認兩款遊戲綁定，必要時選擇伺服器 |
| 按讀取兩款遊戲 | 取得完整角色清單與每名角色詳情，並比較 GitHub main |
| 遇到無法唯一辨識的原神裝備時確認對應 | 保留原有實體 ID，或明確建立另一件物品 |
| 查看逐角色的新舊數值與未知欄位 | 只列實際變動，首次建立同步對應另計。正式資料仍保持原樣 |
| 從預覽按調整裝備對應 | 返回既有選擇，修改後重新產生差異 |
| 按更新網站資料 | 一次保存兩款帳號、原神摘要與去除帳號識別的 API 來源，再讀回確認 |
| 重新整理正式網站 | 顯示最新 main 的紀錄 |

更新前會確認正式網站及 GitHub main 均支援新格式。主線尚未合併本次同步程式時，工具拒絕寫入。預覽後若 GitHub 有其他更新，需重新讀取再比較。更新結果不明時，先按確認更新結果，不自動重送。

本機工作目錄不會被遠端同步結果覆寫。開發時需依既有 Git 流程同步 main，避免拿本機舊帳號資料覆蓋遠端新紀錄。

本輪只核對資料時，可用 `python -m tools.hoyolab_sync.server --preview-only` 啟動。此模式隱藏正式更新按鈕，服務端亦拒絕寫入。

## 登入與保存

Cookie 只送到本機工具，並僅用於向 HoYoLAB 讀取遊戲資料。不掃描瀏覽器或其他帳號資料，不寫入來源庫、網站、日誌或聊天。未選擇保存時，讀取後清除本次登入。

勾選保存後，Mac 使用系統 Keychain，Windows 使用 Credential Locker。只操作本工具自己的服務項目，不採用明文儲存替代方案。可在本機頁移除已保存登入。這台電腦保存的登入不會同步到其他電腦，HoYoLAB 登入失效後仍需重新登入。系統儲存方式依 [keyring 文件](https://keyring.readthedocs.io/en/latest/)實作。

整理後的預覽暫存在本機忽略目錄 `.hoyolab-sync`，只含去除帳號識別的遊戲資料與校驗值，不含登入資訊。每項裝備選擇會連同當時 GitHub revision 保存。工具重啟後可還原上次預覽與對應，不必重做登入或改變原讀取時間。GitHub 正式資料已變更時，舊選擇會清除並提示重新核對。更新成功或取消本輪後清除。

GitHub 使用這台電腦既有的 GitHub CLI 登入。憑證只在請求期間保留於程序內，不放在命令參數或檔案。網站不接收 HoYoLAB Cookie。此版本停用舊網站帳號 POST 更新入口，正式寫入由本機工具處理。

## 資料判定

| 項目 | 採用方式 | 未確認的部分 |
| --- | --- | --- |
| 原神技能 | 以公開技能 ID 對照普攻、戰技與爆發，保留 API 顯示等級。依逐角色與元素的已啟用命座規則，另算基礎等級 | 未知技能不按陣列位置猜測，不通用套用三命戰技、五命爆發。規則或來源情境不明時不反推 |
| 原神詞條次數 | API times 直接對應不含初始的強化次數，計有效總數時每列再加 1 | 不從顯示數值反推強化檔位 |
| 絕區零技能 | 保留官方戰績頁的顯示等級，依逐角色已核對的影畫規則另算五項技能基礎等級。核心 2 至 7 對應 A 至 F，1 對應未升階 | 未核對的規則、未知影畫與不合理等級不反推。核心技能不扣影畫 |
| 絕區零詞條次數 | 同盤完整比對時保留原觀測。新盤僅在 S 級固定增量、整數與整盤預算都通過時推導 | A、B 級與不符合規則的值維持未知 |
| 有效詞條 | 遊戲明確觀測優先。缺少時才採用具名的角色規則，並獨立保存判定 | 規則未涵蓋的詞條仍未知。音擎或武器、命座或影畫、屬性情境改變時停止沿用規則 |

原神的次數與技能轉換參考同 SDK 作者的 [hoyo-buddy 原始實作](https://github.com/seriaati/hoyo-buddy/blob/main/hoyo_buddy/hoyo/clients/gpy.py)及 [GOOD 轉換實作](https://github.com/LeiShi1313/genshin-good-exporter/blob/main/src/lib/convert.js)。技能 ID 對照固定於 [Enka 資料提交](https://github.com/EnkaNetwork/API-docs/tree/9780bb7dc728cf1862de8e080e9d56e60a7c496b/store)。

[原神天賦規則](data/genshin_talent_rules.json)保存公開客戶端資料的逐技能、元素及六個命座核對結果。將戰績等級視為永久投入加命座，是公開同步工具與本次帳號對照支持的推論，未宣稱官方已保證所有情境。遊戲畫面可能含絲柯克或達達利亞的隊伍被動，不據此再從戰績等級扣 1。來源語義不明、技能 ID 不符或結果超出可投入範圍時，基礎值維持未知。

絕區零顯示等級依 [HoYoLAB 官方戰績前端](https://act.hoyolab.com/app/zzz-game-record/pc_9524b22f.js)核對，核心階段依 [HoYoWiki 核心表](https://wiki.hoyolab.com/pc/zzz/entry/618?lang=zh-tw)核對。[逐角色技能加成表](data/zzz_talent_rules.json)保存 38 名角色的影畫核對結果、官方語言版本與校驗值。部分繁中條目漏列支援技，採同一官方條目有明列的簡中或英文內容，差異記在規則來源。

S 級推導表來自本專案 228 盤直接截圖觀測，並非 API 原始次數或官方完整機制表。貓又 5 號盤穿透值 18 的舊次數 0，已回查原圖確認為 +1，修正只套用到同步候選，原始影片觀測保留於歷史資料。

[角色規則](data/effective_rules.json)區分既有逐圖有效標記與公開技能機制支持的用途評估。新增角色依使用者指定，按目前武器、套裝與主詞條判定用途，並在預覽標示。用途評估綁定槽位、套裝與主詞條種類，換成不同配裝時停止沿用。角色規則中的非優先屬性不代表完全沒有數值收益，不能與遊戲原始有效標記混為一談。需要特定反應隊伍才能確認的屬性保持未知。[S 級推導表](data/zzz_roll_rules.json)保存依據、校驗值與人工回查紀錄。

## 證據與相容

原神同步候選使用 schema v3，絕區零使用 v2。舊版仍可驗證，不會為了導入 API 改寫原影片或截圖。

每次不同內容的正規化資料保存到 `imports/hoyolab/<來源ID>.json`。其中不含 UID、暱稱、伺服器、Cookie 或圖片網址。來源 ID 依內容產生，相同資料再次讀取不新增重複來源。原神用 manifest v3 引用 JSON 觀測，絕區零用 syncSources 與 JSON 記錄引用。讀取時間不當成遊戲實際面板觀測時間。

原神保留所有舊面板及指紋。絕區零首次同步前的影片角色紀錄保存在 legacyObservation，後續 API 歷史由不可覆寫的來源 JSON 回查。裝備模板 ID 不能代表實體裝備 ID，配對不明時需要使用者確認。

```sh
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python scripts/validate.py
.venv/bin/python scripts/validate_zzz.py
.venv/bin/python scripts/report.py --check
```
